# 動画にテロップを入れて縦型で書き出す（video/）

ジャービスの動画1本を、字幕付きの縦型リール（1080×1920・30fps・H.264/AAC）にする仕組み。
文字起こしは Mac 内の whisper.cpp で行い、音声を外部に送らない。

## 使い方

```bash
cd ~/dev/ai-jvhiro-lp
zsh video/make.sh IMG_8930.MOV
zsh video/make.sh IMG_8930.MOV --title "見出しの文言" --crop left
zsh video/make.sh "'/Users/hiroki/Movies/IMG_9020.MOV'"   # 絶対パスでも可（Finder からドラッグした形をそのまま。クォート・file:// は自動で除く）
```

Claude Code では `/telop`（動画のパスを貼る → 下書きを直す → 書き出し）と `/caption`（キャプション作成）のスラッシュコマンドで同じ流れを進められる（`.claude/commands/`）。

| 引数 | 意味 |
|---|---|
| `<入力ファイル名>` | iCloud の `Cursor/インスタ投稿/動画/入力` に置いた動画のファイル名（.mov / .mp4）。動画の絶対パスでもよく、入力フォルダ以外にあっても動く（出力先はファイル名だけで決まり従来どおり） |
| `--title "…"` | 冒頭に出す見出し。既定は「50代・非エンジニアが作ったAI相棒」（「非エンジニア」の後で改行）。`|` を入れるとそこで改行 |
| `--crop left/center/right` | 横動画を 9:16 に切るときの位置（既定 center）。縦動画では影響しない |
| `--skip-transcribe` | 文字起こしを省略し、字幕ファイルを直したあとの焼き込みだけやり直す |
| `--title-seconds 2` | 見出しを出す秒数（既定 2）。この間は `q`（質問）のテロップを出さず、見出しが消えた直後から出す（`q` の終了時刻はそのまま） |
| `--no-title` | 冒頭の見出しを出さない |
| `--end 81.2` | その秒数で動画を終える。末尾 0.5 秒は映像と音声をフェードアウト。撮り終わりに手が入ってブレた部分などを切るのに使う（音声が終わった後の時刻を指定する） |

## できあがるもの（すべて iCloud の `Cursor/インスタ投稿/動画/` 配下）

| 場所 | 内容 |
|---|---|
| `字幕/<名前>.srt` | 文字起こしの字幕（木田が直せる） |
| `出力/<名前>_reel.mp4` | 完成した縦型動画。Instagram／TikTok にそのまま上げられる（作り直すと前回分は `出力/前回/` に1世代だけ残る） |
| `出力/確認用/<名前>/<名前>_冒頭.jpg` ほか | 冒頭・中盤・終盤の静止画（確認用）。動画ごとのサブフォルダに入る |
| `カバー/<名前>_cover.png` | リールのカバー画像（1080×1920）。投稿時に「カバーを編集」で選ぶ。見出しは `字幕/<名前>.cover.txt` から読む（下の「カバー画像」参照） |
| `字幕/<名前>.caption.txt` | `/caption` が作る投稿文（Instagram 用と TikTok 用。型は `docs/caption_template.md`） |
| `出力/確認用/<名前>/<名前>_cover_4x5.png` | カバーのうち、プロフィールの一覧で見える範囲（中央 1080×1350）だけを切り抜いたもの。文字がはみ出していないかの確認用 |

## 字幕の直し方

1. `字幕/<名前>.srt` をテキストエディタで開く（番号／時刻／文の3行が1つの字幕）
2. 文を直す。時刻（`00:00:09,780 --> 00:00:15,470`）の形式は変えない
3. ジャービスの発言は、文の先頭に `J:` を付けると**薄いシアン**で表示される（付けなければ白）
   ```
   3
   00:00:09,780 --> 00:00:15,470
   J: 今日の売上は149,947円ですね。
   ```
4. 直したら `--skip-transcribe` を付けて同じコマンドを実行する
   ```bash
   zsh video/make.sh IMG_8930.MOV --skip-transcribe
   ```

`--skip-transcribe` を付けずに実行すると文字起こしをやり直し、既存の字幕は `<名前>.srt.bak-日時` に控えてから上書きする。

- 1行は画面幅（960px）に収まる文字数で自動改行し、行頭に句読点が来ないよう調整する。手で改行したい場所には `|` を入れる
- 話者の自動判別はしていない（whisper.cpp は話者を区別できないため）。色分けは `J:` の手動指定のみ

## 仕組み（make.sh の流れ）

1. 音声を 16kHz モノラルで取り出し、`whisper-cli`（モデル large-v3-turbo、日本語指定）で SRT を作る
2. `render_overlays.py` が SRT と見出しから透明 PNG（1080×1920）を作る。字幕は画面の下から 20% の位置、56px の白文字＋黒縁＋半透明の帯。見出しは 76px、画面上部 22% の位置に 2 秒間、その下に「#ジャービス」
3. ffmpeg で 9:16 に切り出し（`--crop`）→ PNG を重ねる → 音量を 2 パスで標準化（-14 LUFS、TP -1.5）→ libx264（CRF 20）＋ AAC 192k で書き出し

見た目の数値（文字サイズ・位置・色・1行の文字数）は `render_overlays.py` の先頭にまとめてある。

## 必要なもの

- `brew install ffmpeg whisper-cpp`
- `python3` に Pillow（`pip3 install pillow`）
- 文字起こしモデル `ggml-large-v3-turbo.bin`（約1.6GB）は初回に `~/.cache/whisper-cpp/` へ自動取得
- 字幕フォント Noto Sans JP（Bold）は `pdf/fonts/` の woff から `video/woff2ttf.py` で自動変換して `video/fonts/` に置く（git 管理外）

## 処理時間の目安（M2 Pro・34秒の 4K 動画）

文字起こし 3〜4 秒、書き出し 30 秒ほど。

## 要点モードと全文モード（`--mode`）

| モード | 指定 | 画面に出すもの | 元になるファイル |
|---|---|---|---|
| 要点（既定） | `--mode highlight` または省略 | 質問・答えの要点・数字だけ | `字幕/<名前>.highlight.txt` |
| 全文 | `--mode full` | 文字起こしの全文字幕 | `字幕/<名前>.srt` |

要点モードで `highlight.txt` が無いときは、SRT から**下書きを自動で作って止まります**（勝手に書き出さない）。
下書きを短く直してから `--skip-transcribe` を付けて再実行してください。

### highlight.txt の書式

1 行 1 テロップ。「開始秒-終了秒 | 種類 | 文字」。`#` で始まる行はメモ（無視される）。

```
0.0-4.5 | q | 今日の売上は？
9.8-18.4 | n | 149,947円
9.8-18.4 | a | 乳酸菌サプリ24個・病院から1件
```

| 種類 | 意味 | 見た目 |
|---|---|---|
| `q` | 質問 | 白・64px・黒縁・帯なし。画面中央やや上（上から 42%） |
| `a` | 答えの要点 | 薄いシアン・64px・黒縁・半透明の帯。画面下（下から 20%） |
| `n` | 数字の強調 | 白・120px・太い黒縁・帯なし。画面中央やや下（上から 60%） |

- 文字の中で `*…*` で囲んだ部分は強調され、`n` と同じ白で描かれる（例: `コメントに『*最初の一歩*』`。`a` の薄いシアンの中で一語だけ目立たせたいとき）
- 同じ時刻に `n` と `a` を並べると、数字と一言を同時に出せる（`a` が 2 行になっても `n` は帯と重ならない位置に自動でずれる）
- 同じ種類が同じ時刻に重なったときは、先に始まった方だけ出る
- 下書きの振り分けルール：「？」「教えて」「ですか」を含む字幕は `q`、それ以外は `a`。2 桁以上の数字を含む字幕は数字だけの `n` 行も付く。「かしこまりました」「ありがとう」などの相づちはメモ行にして出さない
- `q` の開始時刻は、文言の最初の語（先頭 2 文字）を言い始めた時刻に自動で合う（whisper.cpp の単語単位の時刻で、そのキューの区間だけ再認識する。`video/q_align.py`）。語が見つからないときはキュー開始のままにし、下書きの末尾にその旨のメモが付く。手で直したいときは highlight.txt の時刻を書き換えればそのまま使われる
- 文言を短く直したあとに開始時刻を求め直したいときは、単体でも使える：
  ```bash
  python3 video/q_align.py "$HOME/Library/Mobile Documents/com~apple~CloudDocs/Cursor/インスタ投稿/動画/入力/IMG_8948.MOV" 0.0 10.0 "在庫と仕入れのタイミングは？"
  ```

## テロップの決め方（/telop が highlight.txt を整えるときのルール）

`highlight_draft.py` の下書きは機械的なので、Claude Code がこのルールで整える（木田は直さない。文言の修正依頼が来たときだけ直す）。
実例は iCloud の `字幕/IMG_9006.highlight.txt`（お知らせの掛け合いと突っ込みまで入った回）。時刻の根拠はその中の `#` 行に残す。

### 質問（q）
- 1 つの質問につき q は 1 行。文言は短く（「本日の売上は？」「在庫と仕入れのタイミングは？」）
- **開始**＝文言の最初の語の言い始め。「ジャービス」の呼びかけは含めない。`q_align.py`（whisper -ml 1 の単語時刻）か無音検出で求める：
  ```bash
  python3 video/q_align.py "<動画>" <キュー開始> <キュー終了> "本日の売上は？"
  ```
- **終了**＝ジャービスの相づち「かしこまりました」の言い始めの直前まで延ばす（SRT の次キューの開始を使う）

### 数字（n）と一言（a）
- 金額・個数・％は n（数字だけ。`1,031,506円` `194個` `59.4%`）。その説明は同じ時刻に a（「本日の売上」「乳酸菌サプリ」「薬局A向け」）
- 1 つの SRT キューに数字が 2 つ以上あれば、2 つ目の語の言い始め（`q_align.py` に 2 つ目の語を渡す。例 `"腸活"`）で n／a を切り替える。前後半の表示時間が極端に偏らないようにする（片方が 1 秒未満なら区切りを寄せる）
- 前日比の％はジャービスが発話していれば n（「昨日より下回った」を a）。発話に無ければ出さない（HUD にあっても作らない）
- 「昨日は大口の取引があったため、対比はあまり参考になりません」のような注釈は a で 1 行、発話の間だけ
- 数字は HUD（画面の表示）と整合を確認する。違う・怪しい箇所は**直さずに報告に書く**

### 出さないもの
- 相づち（かしこまりました）・雑談・お礼（ありがとう／こちらこそ）・締め台詞（どういたしまして、○○様。今日もお疲れ様でした／本日もご一緒させていただき…）はテロップにしない。`#` 行で「テロップなし」と残す

### お知らせの掛け合い（動画の後半にある回）
- 前置き「私からお知らせがあります」→ a（発話の間だけ）
- 木田の「何？」→ q（言い始めから、本文の言い始めの直前まで）
- 本文 → a を 2 段階。前半「フォローして、コメントに『*最初の一歩*』」、後半「無料PDFをDMでお届け」。切り替えは「無料の」の言い始め。`*…*` は強調（白）
- コメントの合言葉（例の『最初の一歩』）は回ごとに変わる。その回の SRT でジャービスが言った語（「コメントに『○○』とだけお書きください」の ○○）をそのまま使い、勝手に固定しない
- 木田の突っ込み（「宣伝か笑」等）→ q。ジャービスの返しは、発話に無いことを足さず執事口調で 2〜3 行に要約して a で出す（例「撮影中でございますので」「宣伝も、時々入れております」「ご容赦くださいませ」）。オチになる一言を最後の行に置き、木田の次の発話の直前まで残す

### 末尾の判定
```bash
python3 video/last_voice.py "<動画>" --srt "字幕/<名前>.srt"
```
- 無音検出（-35dB・1 秒以上）で「最後の声の終わり」を求める。それより後に始まる SRT キューは幻聴なので、`<名前>.srt.bak` に控えてから SRT から削除する
- `--end` は最後の声の約 2 秒後（`last_voice.py` の提案値。末尾 0.5 秒はフェード）。撮り終わりにカメラのブレがあればその直前（終盤の静止画で確認）

### 長い無音を詰める（`--cut`）
- 「OK、ありがとう」の後など、返答待ちの無音が 3 秒以上あるときは `--cut 開始-終了`（元動画の秒。複数可）で取り除ける。highlight.txt の時刻と `--end` は元動画の秒のまま書いてよい（make.sh が切った分をずらす）
- 画面の中に 1 秒周期で点滅する時計（壁のデジタル時計のコロン）があるので、**切る長さはちょうど整数秒**にする（例 3.0 秒）。整数秒なら点滅のリズムがそのまま繋がる。切る位置は点滅の切り替わり直前（毎秒 .15 か .65）に置くと、繋ぎ目の直後に「予定どおりの点滅」が来て目立たない
- 映像はクロスフェードしない（コロンの点灯と消灯が重なって二重に見える）。音声だけ前後 0.05 秒フェードする（make.sh が自動）
- 無音を全部は消さず、会話の間として 0.5〜1 秒残す。1.3 秒程度の短い間は詰めない（詰まった印象になる）
- 分の桁が変わる瞬間をまたいで切らない（切る前後で時刻の表示が飛ぶ）
  ```bash
  zsh video/make.sh "<動画>" --skip-transcribe --end 60.0 --cut 6.15-9.15 --cut 34.65-37.65
  ```
- 点滅の位相と分の桁は、時計の部分を 10fps で切り出して明るさを測ると確認できる（IMG_9068 の回で実施：毎秒 .7 点灯／.2 消灯）

### カバーの見出し（cover.txt）
- SRT から見出し 2 行（1 行 10〜13 文字。数字か意外な一言。2 行目に数字や決め台詞）。Day 番号は `字幕/*.cover.txt` にある Day の最大 + 1
- 書式は下の「カバー画像」節。モニターに重なるときは `y: 0.93` を足す

### 文言の修正が来たら
`highlight.txt` か `cover.txt` を直して、同じ `--end` で再実行する（文字起こしはしない）：
```bash
zsh video/make.sh "<同じ入力>" --skip-transcribe --end <同じ値>
```

## カバー画像（`video/make_cover.py`）

`make.sh` の最後に自動で作られる。Instagram のプロフィール一覧で「何の回か」がわかるように、動画の 1 コマを暗くした上に大きな見出しを載せる。

- 上に大きな「Day N」のバッジ（黄 #FFD400・黒文字。4:5 範囲の上端から 5.5% の位置）、下寄りに見出し 2 行（1 行目 白・2 行目 黄、太い黒縁。見出しの下端が 4:5 範囲の 85% の位置＝モニターの下あたり）。一覧（3 列）のサムネは幅 360px ほどで文字が 1/3 に縮むため、小さな文字は置かない
- 文字はすべて中央の 1080×1350（4:5）に収めている。一覧ではその範囲だけが見える
- 背景は `highlight.txt` の最初の `q`（質問）の中間時刻の 1 コマ（テロップを重ねる前の元動画から切り出す）

### 見出しの書き方（`字幕/<名前>.cover.txt`）

```
Day 4
100万超えの朝
大口が1件入った日
```

1 行目が Day 番号（`4` だけでも可）、2〜3 行目が見出し（1 行 10〜13 文字。長いと自動で小さくなる）。`#` で始まる行はメモ。
見出しがモニターに重なる回は `y: 0.93` の行を足すと、見出しの下端がその位置（4:5 範囲の上端 0〜下端 1.0 の割合。既定 0.85）に下がる（Day 1〜3 で使用）。コマンド引数 `--title-y 0.93` でも同じで、引数が優先。
このファイルが無いときは「見出し未設定」のカバーを作って止まらずに進む。書いてから `--skip-transcribe` を付けて再実行すれば差し替わる。

カバーだけ作り直したいときは単体でも使える（`--at 秒` で背景のコマを指定できる）：

```bash
python3 video/make_cover.py --input "$HOME/Library/Mobile Documents/com~apple~CloudDocs/Cursor/インスタ投稿/動画/入力/IMG_8970.MOV" \
  --cover-txt "$HOME/Library/Mobile Documents/com~apple~CloudDocs/Cursor/インスタ投稿/動画/字幕/IMG_8970.cover.txt" \
  --font-bold video/fonts/NotoSansJP-Bold.ttf --at 6.5 \
  --out "$HOME/Library/Mobile Documents/com~apple~CloudDocs/Cursor/インスタ投稿/動画/カバー/IMG_8970_cover.png"
```

色は引数で変えられる：`--badge "#FFD400"`（バッジの色）、`--badge-text "#000000"`（バッジ文字の色。省略時はバッジが明るければ黒、暗ければ白）、`--accent "#FFD400"`（見出し 2 行目の色。1 行目は常に白）。既定は黄バッジ（#FFD400）＋黒文字、2 行目も黄（2026-09-17 決定のA案）。

見た目の数値（明度・文字サイズ・位置・色）は `video/make_cover.py` の先頭にまとめてある。
