## /kata — 当たり投稿の「型」を一覧にまとめる（読む → 一覧を更新 → コミットまで）

引数: `$ARGUMENTS`

木田が Instagram で見つけた伸びている投稿のスクショを iCloud `Cursor/インスタ投稿/当たり投稿/<撮った日付>/` に入れたあと、これを打つだけで型の一覧の更新からコミットまで終わらせる。
当たり投稿フォルダの絶対パスは `/Users/hiroki/Library/Mobile Documents/com~apple~CloudDocs/Cursor/インスタ投稿/当たり投稿/`。一覧は `marketing/patterns/当たり投稿の型.md`（正本）と iCloud `Cursor/インスタ投稿/マーケ調査/当たり投稿の型.md`（コピー）。

「型」とは中身ではなく**作り方**のこと：最初の 1 行の引きつけ方、見せる順番、数字の出し方、カバーの見出しの形、キャプションの組み立て など。

### 1. 事前確認（どれか 1 つでも通らなければ、作業に入らず伝えて停止）

- `git status` がクリーンであること。クリーンでなければ変更の一覧を木田に伝えて停止。クリーンなら `git pull --ff-only` で同期する
- 対象フォルダを決める：引数があれば `当たり投稿/<引数>/`。引数が空なら `当たり投稿/` の中で名前（日付）がいちばん新しいフォルダ。フォルダが 1 つも無ければ「当たり投稿/ に日付フォルダがありません」と伝えて停止
- 対象フォルダが一覧の「読み込んだフォルダ」に既にある場合：その行に「読み取れなかった画像」の名前が残っていれば、**その画像だけ**を対象にして 3 へ進む（読めた画像は二度数えない）。残っていなければ「読み込み済みです。もう一度数えるなら言ってください」と伝えて停止
- 対象フォルダの画像（PNG／JPG／HEIC）の枚数を数え、すべて Mac にダウンロード済みで開けることを確認する（`ls -l` でサイズ 0 や `.icloud` のファイルが無いこと、`sips -g pixelWidth` で開けること）。0 枚、または未ダウンロードのものがあれば、iCloud の同期待ちの可能性を伝えて停止
- `marketing/patterns/当たり投稿の型.md` が無ければ伝えて停止（消さない・作り直さない）

### 2. 一覧の今の中身を読む

- `marketing/patterns/当たり投稿の型.md` の「決まり」と「型の一覧」を読み、既にある型の名前と作りを把握する（同じ型を別名で二重に足さないため）

### 3. 画像を 1 枚ずつ読み、型だけを取り出す

- 画像を Read で開く（1 枚ずつ）。1 枚の画像に複数の投稿が写っていることもあれば、1 つの投稿がカバー・冒頭・キャプションの複数枚に分かれていることもある。まず画像を**投稿ごとにまとめ**（同じ投稿かどうかはカバー・投稿者の表示・前後の並びで判断し、迷うときは別の投稿として数えず「同じ投稿の可能性あり」と報告に書く）、型は**投稿単位**で取り出す。同じ投稿の同じ型は 1 件とだけ数える
- 各投稿から読み取るのは**作り方だけ**。次の観点で見る：
  - 最初の 1 行（カバーや冒頭）の引きつけ方（問いかけ／数字／逆説／宣言 など）
  - 見せる順番（結論が先か、過程が先か、数字がいつ出るか）
  - 数字の出し方（金額の桁、％、件数、ビフォー・アフター）
  - カバーの見出しの形（行数、文字数、色、「〜したら」「〜の人へ」などの形）
  - キャプションの組み立て（1 行目、自己紹介の位置、導線の置き方）
- **書かないもの**：ほかの人のアカウント名、顔の説明、投稿の文章そのもの。言い回しを示すときは数語の短い例にとどめる（1 文をそのまま写さない）
- 読めない画像・投稿でない画像は推測で埋めず、「読み取れなかった画像」として報告に挙げる
- 画像をリポジトリにコピーしない（`marketing/` に画像を置かない）

### 4. 一覧を更新する

- 既にある型と同じ作りなら、新しく足さずにその型の「見た件数」をその型を見た**投稿の数**だけ増やし、「最後に見た日」は既存の日付と対象フォルダの日付の**新しい方**にする（古いフォルダを後から読んでも日付が過去に戻らないように）
- 新しい型なら、一覧の書式（ファイル内のコメントの書式）で通し番号の次の番号として足す。「見つけた日」は対象フォルダの日付
- 「@ai_jvhiro で使うなら」は 1 行。アカウントの軸（稼ぎ方ではなく、自分の仕事が楽になる実例を見せる）に合う使い方で書く
- 稼げる・儲かる・月〇万円・副業など成果を約束する型は「印」に「**@ai_jvhiro では使わない**」と書く（型の記録としては残す）
- 「読み込んだフォルダ」に対象フォルダの日付・画像の枚数・投稿の数を 1 行足す。読み取れなかった画像があればその行に「読み取れなかった画像：<ファイル名>」と書き残す（後で同じフォルダを `/kata` したときにその画像だけ再処理するため）。再処理で読めたら、その名前を行から消す
- 更新後、同じ内容を iCloud `マーケ調査/当たり投稿の型.md` にコピーし、`cmp` で一致を確かめる

### 5. 報告（この順・見出し付き）

1. 読んだフォルダと画像の枚数
2. 増えた型（番号・名前・1 行の作り）
3. 件数が増えた型（番号・名前・件数の前後）
4. 「@ai_jvhiro では使わない」の印を付けた型
5. 読み取れなかった画像
6. 一覧の場所（正本と iCloud コピーの 2 パス）

### 6. 締め（/telop・/caption と同じ）

リポジトリ内のファイル（一覧・このコマンド・README など）を追加・変更した場合は、次を行う。変更が無ければ何もしない。画像はコミットしない。

1. Codex（OpenAI）で差分をレビューする。指摘を重大／中／軽微に分け、**重大なものだけ直す**（中・軽微は報告に載せる）。`/codex:review` が使えない環境では次を使う（新規ファイルは先に `git add -N`）：
   ```bash
   git diff HEAD | codex exec -s read-only "この差分をコードレビューし、問題点を重大／中／軽微に分けて日本語で報告してください"
   ```
   Codex が実行できない（利用上限・未ログインなど）ときは省略して、その旨を伝える
2. コミットして `git push origin main` まで行い、コミット ID を木田に伝える
