## /insight — 週 1 回のインサイト分析（分析 → レポート保存 → コミットまで）

引数: `$ARGUMENTS`

木田が Instagram のインサイトのスクショを iCloud `Cursor/インスタ投稿/インサイト/<日付>/` に入れたあと、これを打つだけで sns-marketer の分析からコミットまで終わらせる。
インサイトフォルダの絶対パスは `/Users/hiroki/Library/Mobile Documents/com~apple~CloudDocs/Cursor/インスタ投稿/インサイト/`。レポートの保存先は `marketing/reports/<日付>_インサイト分析.md`（正本）と iCloud `Cursor/インスタ投稿/マーケ調査/`（同じファイル名）。

### 1. 事前確認（どれか 1 つでも通らなければ、作業に入らず伝えて停止）

- `git status` がクリーンであること。クリーンでなければ変更の一覧を木田に伝えて停止。クリーンなら `git pull --ff-only` で同期する
- 対象フォルダを決める：引数があれば `インサイト/<引数>/`。引数が空なら `インサイト/` の中で名前（日付）がいちばん新しいフォルダ。フォルダが無ければ伝えて停止
- 対象フォルダの画像（PNG／JPG／HEIC）の枚数を数え、すべて Mac にダウンロード済みで開けることを確認する（`ls -l` でサイズ 0 や `.icloud` のファイルが無いこと、`sips -g pixelWidth` などで開けること）。0 枚、または未ダウンロードのものがあれば、iCloud の同期待ちの可能性を伝えて停止
- `marketing/reports/<日付>_インサイト分析.md` が既にある場合は、上書きせず木田に確認する（「上書きしてよいか／別名にするか／やめるか」の 1 行）。返事があるまで進まない
- sns-marketer がこのセッションでサブエージェントとして呼び出せること。呼べない場合は汎用エージェントで代行せず、「新しいチャットを開いてやり直してください」と伝えて停止

### 2. 木田に 1 回だけ尋ねる（導線の数字）

- 対象フォルダの中にテキストのメモ（`.txt`／`.md`）があればそれを読み、尋ねない
- 無ければ次の 1 行だけ出して待つ：
  > 前回の分析以降の各回について、合言葉のコメント件数と DM で PDF を送った件数を教えてください（「なし」でも進みます）
- 「なし」と言われたらそのまま進む（レポートには「未提供」と書かせる）

### 3. スクショの前提（sns-marketer への依頼にそのまま添える）

- 1 本につき 3 種類の画面がある
  - **A**：概要の一番上（Day N のカバー、いいね等の数、閲覧数・閲覧者・平均再生時間・フォロー数）
  - **B**：閲覧数の推移とスキップ率・シェア率・いいね率（Day N の表示なし）
  - **C**：再生時間の折れ線グラフ（横軸の右端が動画の長さ）と閲覧数の上位のソース
- 基本は「その週に投稿した回を、1 本につき A・B・C の 3 枚」。それより前の回の A（1 枚だけ）は任意で、入っている週も入っていない週もある。A しか無い回は、取れる項目だけ記録し、他は空欄にする。前の回のスクショが無いことを問題として扱わない
- ファイル名の順は撮影順と一致するとは限らない。どの回かは Day N のカバー、画面上部の時刻、前後の並びで判断する。判断できない画像は推測で割り当てず「判別できなかった画像」として報告する

### 4. sns-marketer への依頼（Agent ツールで `subagent_type: sns-marketer`。1 回の依頼に次を全部入れる）

メイン側で先に集めて添える事実：対象フォルダの絶対パスと画像の一覧（枚数）、2 で得たコメント件数・DM 送付数（または「未提供」）、3 の前提、保存先 2 か所の絶対パス、今日の日付。

依頼内容：
- すべての画像を読み、回ごとの数字の一覧表を作る。列は：閲覧数／閲覧者／平均再生時間／動画の長さ／スキップ率／シェア率／いいね率／いいね・コメント・保存・シェアの数／フォロー数／上位ソースの割合／再生時間グラフから読み取れる冒頭の落ち方（「おおよそ」と明記）。読めない数字は空欄。数字を作らない
- `marketing/reports/` の過去のインサイト分析と比べる。同じ回のスクショが今回もある場合は、数字がどれだけ動いたかも示す。今回スクショが無い過去の回は、過去のレポートの数字を「前回時点の値」と明記して比較に使う
- 各回の中身（テーマ、冒頭、カバー見出し）を iCloud `動画/字幕/` の cover.txt・highlight.txt・SRT と `動画/撮影メモ/` から把握し、数字と照らし合わせる
- `marketing/reports/` の「採用した変更」と「投稿前チェック」のレポートを読み、採用した変更（見出しの型、先出しテロップなど）が効いたかどうかを「裏づけあり／裏づけなし／まだ判断できない」で判定する
- コメント件数・DM 送付数があれば、閲覧数に対する割合を出し、導線の効き具合を書く
- 比べるときの注意：投稿からの日数が違うので閲覧数をそのまま優劣にしない。スキップ率、平均再生時間÷動画の長さ、上位ソースの割合など日数に左右されにくい数字を重く見る。本数が少ないので断定せず「傾向」「可能性」と書き分ける。因果を言い切らない
- レポートは担当の定義どおり 6 章の型。「次の回への具体案」は短い箇条書きで、そのまま撮影や見出しづくりに使える言い方にする（`/satsuei`・`/telop`・`/caption` が毎日読むため）
- 保存先：正本 `marketing/reports/<日付>_インサイト分析.md`、同じ内容を iCloud `マーケ調査/` に同じファイル名で書く。書き込みはこの 2 か所だけ
- 最後に、一覧表・今回の結論（3 行）・採用した変更の判定・次の回への具体案・読み取れなかった数字と判別できなかった画像・書いた 2 パスを返答に載せる

### 5. メイン側の確認

- 一覧表から 3 本分を選び、元のスクショ（Read で画像を開く）と数字を突き合わせる。読み違いがあれば sns-marketer に直させる（SendMessage で同じエージェントに。やり直しは 1 回まで）
- レポートが 2 か所に同じ内容で出ていること（`cmp`）。稼ぎ方をあおる提案（「AIで月〇万円」「副業」「稼げる」の類）が入っていないこと（`grep`）
- スクショの画像はリポジトリに入れない（`marketing/` にコピーしない。`git status` に画像が出ていないこと）

### 6. 締め

- Codex（OpenAI）で差分をレビューする。指摘を重大／中／軽微に分け、**重大なものだけ直す**（中・軽微は報告に載せる）。`/codex:review` が使えない環境では次を使う（新規ファイルは先に `git add -N`）：
  ```bash
  git diff HEAD | codex exec -s read-only "この差分をコードレビューし、問題点を重大／中／軽微に分けて日本語で報告してください"
  ```
  Codex が実行できない（利用上限・未ログインなど）ときは省略して、その旨を伝える
- レポートをコミットして `git push origin main`。メディア（画像・動画）はコミットしない
- 木田への報告（この順・見出し付き）：今回の結論（3 行）／数字の一覧表／採用した変更の判定／次の回への具体案／読み取れなかった数字と判別できなかった画像／Codex の指摘と対応（または省略した旨）／コミット ID／iCloud 側のファイル名

### 注意

- 分析・レポート作成は sns-marketer に任せる。メイン側は事実集め・検算・コミットだけを行い、数字を自分で書き足さない
- 製品名・取引先名はレポートにも出さない（sns-marketer の定義どおり）。合言葉は回ごとに変わるので固定しない
