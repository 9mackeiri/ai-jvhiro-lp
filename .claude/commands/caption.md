## /caption — 投稿キャプションを作る

引数: `$ARGUMENTS`

型は `docs/caption_template.md`。**必ず先に読み、そのとおりの構成で書く**。

### 1. 動画名の受け取り

- 引数があればそれを動画名にする（`IMG_9020.MOV` `IMG_9020` どちらでも。パスならファイル名だけ取り出す）
- 引数が空のとき：
  - このセッションで `/telop` を実行した動画名を覚えていれば、次の 1 行だけ出して待つ：
    > 動画名は **IMG_XXXX** でよければ Enter（違う場合は動画名を貼ってください）
    空の返答・「OK」ならその名前で進む
  - 覚えていなければ、次の 1 行だけ出して待つ：
    > 動画名（IMG_XXXX）を貼ってください
    （参考に iCloud `動画/出力/` の `*_reel.mp4` の新しい順 3 件を添えてよい）

### 2. 材料を読む（iCloud `Cursor/インスタ投稿/動画/字幕/`）

- `<名前>.cover.txt` … Day 番号と見出し 2 行（1 行目「Day N｜…」に使う）
- `<名前>.highlight.txt` … 質問 q・数字 n・一言 a（`#` 行は読まない）
- `<名前>.srt` … 実際の言い回し、AI の返し、お知らせの掛け合いの有無
- 合言葉 … SRT でジャービスが言う「コメントに『○○』とだけお書きください」の ○○。毎回変わるので必ずその回の SRT から取り、型の `<合言葉>` に入れる（SRT に無ければ木田に聞く）
- 無いファイルはあるものだけで作り、無かったものを報告に書く

### 2b. 撮影メモと最新レポートを読む（1 行目・型・ハッシュタグを決める前に）

- その日の撮影メモ（iCloud `動画/撮影メモ/` にある当日または最新の `YYYY-MM-DD_DayN.md`。`/satsuei` が作る）があれば読む。無ければ飛ばす
- 最新レポートを読む（共通ルール）：
- `marketing/reports/` の中から、ファイル名の日付がいちばん新しいものを**それぞれ 1 本ずつ**読む：名前に「インサイト分析」を含むもの／「投稿前チェック」を含むもの／「採用した変更」を含むもの
- 読むのは主に「今回の結論」と「次の回への具体案」の章。該当するレポートが無い場合は、無いものは読まずに先へ進む
- レポートの内容は提案。`README.md`・`docs/caption_template.md`・各コマンドの既存ルールと食い違うときは既存ルールを優先し、食い違いを木田に伝える
- Web 検索や sns-marketer の呼び出しはしない（重い調査・分析は週 1 回のインサイト分析に寄せる）
- `docs/caption_template.md` の決まり（お知らせの型、LINE や URL を書かない、TikTok の扱いなど）が**常に優先**。撮影メモ・レポートはその範囲内での参考にする

### 3. 書く

- `docs/caption_template.md` の Instagram 用・TikTok 用をそのままの順で埋める。固定文は変えない（変えるのは Day N｜見出し・見どころのブロック・`<合言葉>` だけ）
- 見どころは 3〜6 行。数字は SRT／highlight.txt にあるものだけ。製品名・取引先名は出さない
- お知らせの掛け合いがある回（highlight.txt に「お知らせ」や合言葉の a がある）は、見どころの最後に型の定型 1 行を入れる

### 4. 保存と表示

- `字幕/<名前>.caption.txt` に「Instagram 用 → `----` → TikTok 用」で保存（既にあれば `.caption.txt.bak-日時` に控えてから上書き）
- 2 本とも画面に表示し、最後に 1 行「直したい所があれば言ってください。そのまま使うならコピーして貼ってください」

### 5. 締め（道具や説明書を書き換えた場合）

この作業の途中でリポジトリ内のファイル（`video/make.sh`・README・コマンド・スクリプトなど）を追加・変更した場合は、次を行う。変更が無ければ何もしない。動画・画像などのメディアはコミットしない。

1. Codex（OpenAI）で差分をレビューする。指摘を重大／中／軽微に分け、**重大なものだけ直す**（中・軽微は報告に載せる）。`/codex:review` が使えない環境では次を使う（新規ファイルは先に `git add -N`）：
   ```bash
   git diff HEAD | codex exec -s read-only "この差分をコードレビューし、問題点を重大／中／軽微に分けて日本語で報告してください"
   ```
   Codex が実行できない（利用上限・未ログインなど）ときは省略して、その旨を伝える
2. コミットして `git push origin main` まで行い、コミット ID を木田に伝える

### 注意

- キャプションのファイルはコミットしない
- コメントの合言葉は毎回変わる（その回の発話に合わせる）。無料PDF・DM の導線は LP に固定。変えるときは木田に確認する
- 投稿文・コメント返信・DM に「LINE」の語と lin.ee のリンクを出さない（Meta のアカウント停止リスク。型の冒頭ルール参照）
