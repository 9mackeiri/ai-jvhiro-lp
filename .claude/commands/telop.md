## /telop — 動画にテロップを入れて書き出す（途中で止めない）

引数: `$ARGUMENTS`

ルールの本文は `video/README.md` の「テロップの決め方」節。**必ず先に読む**。実例は iCloud の `字幕/IMG_9006.highlight.txt`。
作業フォルダは iCloud の `Cursor/インスタ投稿/動画/`（以下 `字幕/` `出力/` `カバー/` はその中）。

### 1. 入力の受け取り

- 引数が空 → 次の 1 行だけ聞いて待つ：
  > 動画のパスを貼ってください（Finder からドラッグした形でOK。入力フォルダ内ならファイル名だけでも可）
- 受け取った文字列は**そのまま** make.sh の第 1 引数に渡す（クォート・`file://`・`~/` は make.sh が除く。自分で加工しない）
- 動画名 `IMG_XXXX`（拡張子なし）をセッションで覚える（`/caption` の既定値）

### 2. 文字起こしと下書き

```bash
cd ~/dev/ai-jvhiro-lp && zsh video/make.sh <受け取った文字列>
```
- `字幕/<名前>.srt` と、下書き `字幕/<名前>.highlight.txt` ができて止まる（仕様）。木田には聞かず 3 へ進む
- 既に highlight.txt があって止まらなかった場合（作り直しの回）は、そのまま 4 へ

### 3. 末尾の判定（SRT の幻聴を消す）

```bash
python3 video/last_voice.py "<動画のパス>" --srt "字幕/<名前>.srt"
```
- 「最後の声より後に始まる字幕」があれば、`字幕/<名前>.srt.bak` に控えてから SRT から削除する（cp してから編集）
- `--end` は提案値（最後の声の約 2 秒後）。終盤の静止画で撮り終わりのブレが見えたらその直前にする（木田から指示があった場合）

### 3b. 撮影メモと最新レポートを読む（4・5 の案を出す前に）

- その日の撮影メモ（iCloud `動画/撮影メモ/` にある当日または最新の `YYYY-MM-DD_DayN.md`。`/satsuei` が作る）があれば読む。無ければ飛ばす
- 最新レポートを読む（共通ルール）：
- `marketing/reports/` の中から、ファイル名の日付がいちばん新しいものを**それぞれ 1 本ずつ**読む：名前に「インサイト分析」を含むもの／「投稿前チェック」を含むもの／「採用した変更」を含むもの
- 読むのは主に「今回の結論」と「次の回への具体案」の章。該当するレポートが無い場合は、無いものは読まずに先へ進む
- レポートの内容は提案。`README.md`・`docs/caption_template.md`・各コマンドの既存ルールと食い違うときは既存ルールを優先し、食い違いを木田に伝える
- Web 検索や sns-marketer の呼び出しはしない（重い調査・分析は週 1 回のインサイト分析に寄せる）
- これらを踏まえて 4（要点）と 5（カバー見出し）の案を出す。**撮影メモの見出し候補と実際に撮れた内容が合わない場合は、実際の内容（SRT）を優先する**

### 4. highlight.txt を整える（Claude Code が行う。木田は直さない）

`video/README.md` の「テロップの決め方」どおりに、下書きを書き直す：
- q は 1 回。開始は `q_align.py` で最初の語の言い始め、終了は「かしこまりました」の言い始めの直前
- 数字は n、説明は a。キューに数字が 2 つあれば `q_align.py` に 2 つ目の語を渡して切り替え時刻を取る
- 前日比％は発話にあれば n、なければ出さない。注釈は a で 1 行
- 相づち・雑談・お礼・締めは出さない（`#` 行で残す）
- お知らせの掛け合い・突っ込みがある回は README の型どおり（`*…*` で強調）
- 本文のコメントの合言葉は毎回変わる。SRT の発話どおりの語を `*…*` で入れる（README の例『最初の一歩』をそのまま使わない）
- 各行の上に `# --- 根拠（語の時刻など） ---` を残す
- 数字が HUD と合わないなど怪しい箇所は直さず、報告に書く

### 5. カバーの見出し

- `字幕/*.cover.txt` の Day の最大 + 1 を Day 番号にする
- SRT から見出し 2 行（1 行 10〜13 文字。2 行目に数字か決め台詞）を決め、`字幕/<名前>.cover.txt` に書く（書式は README「カバー画像」）

### 6. 書き出し

```bash
cd ~/dev/ai-jvhiro-lp && zsh video/make.sh <同じ文字列> --skip-transcribe --end <3 で決めた値>
```
（1 回目に `--crop` などを付けていたら同じものを付ける）
- `出力/<名前>_reel.mp4`・`出力/確認用/<名前>/`・`カバー/<名前>_cover.png` ができる
- `出力/確認用/<名前>/<名前>_cover_4x5.png` を見て、見出しがモニターに重なっていれば cover.txt に `y: 0.93` を足してカバーだけ作り直す（`video/make_cover.py` 単体。README 参照）

### 7. 報告（必ずこの順・見出し付き）

1. **SRT 全文**（幻聴を削除した後のもの）
2. **highlight.txt**（整えた後の全文）
3. **各テロップの時刻と根拠**（q の開始語の時刻、n/a の切り替え語の時刻、掛け合いの区切り）
4. **怪しい箇所**（HUD と数字が合わない、認識が不確かな語。無ければ「なし」）
5. **末尾の判定**（最後の声の終わり、削除した幻聴キュー、`--end` の値）
6. **完成動画の長さ**（`ffprobe` の秒数）
7. **カバーの見出しと根拠**（Day 番号・2 行・元になった発話）
8. **コード変更の有無**（`video/` のスクリプトを変えたか。変えていなければ「なし」）
最後に 1 行「文言を直すときは、その箇所を言ってください。`/caption` でキャプションも作れます」

### 8. 文言の修正が来たら

- `字幕/<名前>.highlight.txt`（テロップ）か `字幕/<名前>.cover.txt`（カバー）を直す
- 同じ入力・同じ `--end` で再実行（文字起こしはしない）：
  ```bash
  cd ~/dev/ai-jvhiro-lp && zsh video/make.sh <同じ文字列> --skip-transcribe --end <同じ値>
  ```
- 直した行と再生成したファイルだけを短く報告する

### 9. 締め（道具や説明書を書き換えた場合）

この作業の途中でリポジトリ内のファイル（`video/make.sh`・README・コマンド・スクリプトなど）を追加・変更した場合は、次を行う。変更が無ければ何もしない。動画・画像などのメディアはコミットしない。

1. Codex（OpenAI）で差分をレビューする。指摘を重大／中／軽微に分け、**重大なものだけ直す**（中・軽微は報告に載せる）。`/codex:review` が使えない環境では次を使う（新規ファイルは先に `git add -N`）：
   ```bash
   git diff HEAD | codex exec -s read-only "この差分をコードレビューし、問題点を重大／中／軽微に分けて日本語で報告してください"
   ```
   Codex が実行できない（利用上限・未ログインなど）ときは省略して、その旨を伝える
2. コミットして `git push origin main` まで行い、コミット ID を木田に伝える

### 注意

- 動画・音声・字幕・画像はコミットしない（`.gitignore` 済み）
- iCloud で未取得（dataless）の動画は取得に 10 分以上かかることがある。止まって見えたら「iCloud から取得中」と伝える
- 既存の SRT を作り直すと `.srt.bak-日時` が残る。`.srt.bak`（幻聴削除前）とは別物
